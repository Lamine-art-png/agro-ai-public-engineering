# Public Disclosure Boundary

## Safe to publish

- General engineering principles
- Synthetic examples
- High-level project categories
- Generic validation techniques
- Public contact information
- Non-customer-specific screenshots approved for publication

## Never publish here

- Production source code
- Internal architecture diagrams
- Customer names or records without written authorization
- Credentials, tokens, certificates, or environment files
- Cloud account, project, role, queue, bucket, or database identifiers
- Internal prompts, model routing, evaluations, or proprietary decision logic
- Connector authorization flows or provider-specific implementation details
- Pricing, contracts, proposals, or internal delivery material
- Vulnerability details that could facilitate exploitation

## Review rule

A file is publishable only when it remains safe even if read by a competitor, attacker, customer security team, regulator, journalist, and search engine.
